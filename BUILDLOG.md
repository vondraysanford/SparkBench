## 2026-09-13 · GLM-5.3-Flash across both Sparks (detour — not a SparkBench condition)

- **Worked:** the [MiaAI-Lab EXL3 recipe](https://github.com/MiaAI-Lab/GLM-5.3-Flash-EXL3-2x-DGX-Sparks) put a 320B MoE at 4 bpw across both nodes with tensor parallel 2 in one afternoon. Its preflight caught both misconfigurations before anything ran: a worker RoCE device with an empty GID table, then an interface name that did not exist on the worker. Weights (164 GiB, 120 shards) rsynced head → worker over link A at ~391 MB/s. Health 200; `17 × 23 → 391` at temperature 0; a two-sentence DGX Spark description and a Fibonacci function with a short reasoning trace at default sampling. VS Code Copilot Chat drives it as a custom OpenAI-compatible model. First agentic test: the model built [SparkDash](https://github.com/vondraysanford/SparkDash), a live dashboard for its own server, in one session — 4 commits, 16 passing tests.
- **Broke:** Docker was preinstalled on the worker but `admin` was not in the `docker` group. `python3 -m venv` needed `python3-venv` on Ubuntu 24.04 before the Hugging Face CLI would install. The two worker CX-7 lines were left at the recipe's defaults (`f0` port), so preflight refused once and Gloo died once (`Unable to find address for: enp1s0f0np0`). The very first reply after boot was 323 tokens of unrelated HTML — it overlapped the boot warmup; every reply after that was clean. VS Code threw `ERR_ADDRESS_UNREACHABLE` on `spark-927a.local` while `curl` worked; the LAN IP plus macOS Local Network permission fixed it.
- **Surprised:** each Spark exposes four RoCE devices, and only the two with an IPv4-mapped GID are cabled — the port mapping and GID index now live in `infra/cluster.md` (closing its first open item). The rsync over a 200 Gbps link ran at ~3 Gbps because rsync and NVMe set the pace, not the fabric. Why this stays out of the experiment: it is a community overlay image rather than the pinned NGC container, and the checkpoint is not in NVIDIA's support matrix — exactly the late addition the pre-registration exists to refuse. Stop the GLM cluster before Phase 1 training; it holds ~85 % of both nodes.
- **Capture:** screenshot of the preflight OK block with both hostnames and the 164 GiB rsync in flight; the terminal with health `200` and `391`. Post-worthy: a GIF of SparkDash charting the tokens/s of the model that wrote it (capture list in that repo's `evidence/`). Throughput numbers above are anecdotal; nothing enters `bench/results/` until measured with `vllm bench`.
